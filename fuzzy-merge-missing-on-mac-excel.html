Power Query fuzzy merge on Mac Excel: what is reported missing, and what to do instead

Sources last checked 2026-11-11.

You have two tables of company names. One says "Acme Ltd". The other says "ACME Limited". A normal merge finds nothing, so you go looking for the "Use fuzzy matching" checkbox in Power Query. On a Mac, many people report that it is not there.

Short answer: check your own Merge dialog first. If the checkbox is missing, the free fix is to clean both columns (case, punctuation, spacing, common endings like Ltd) and then merge with an ordinary exact match. That fix handles more than you would expect. It stops working when the spelling differences are not just case and punctuation. This page covers all of it, in that order.

Check this first: is the checkbox really missing on your Mac?

We could not settle this from documentation, so here is what we found and what we could not.

What Microsoft's page says. Microsoft's support article "Create a fuzzy match (Power Query)" describes the feature: in the Merge dialog you tick Use fuzzy matching to perform the merge, then set a Similarity Threshold (default 0.80), Ignore case, Maximum number of matches, and an optional Transformation table. It says fuzzy matching works only on text columns in merge operations, and that Power Query uses the Jaccard similarity algorithm. (Read 2026-11-11.)

What we could not confirm. The article has an "Applies To" list near the top. When we opened the page on 2026-11-11 the list came back empty in the text we could read, so we could not check which Excel versions and platforms it names. An earlier reading on 2026-11-10 relied on that Applies-To metadata, not on a release note or a plain sentence saying "not on Mac". Treat the Mac absence as inferred from metadata as of 2026-11-10 and not rechecked. Microsoft's page does not, in the text we could read, state "not available on Mac" anywhere.

What a Microsoft MVP posted. On the Microsoft Community Hub, a post dated 2024-07-10 by an MVP from SumProduct says that on a Mac "you can't" set up the fuzzy match "because Fuzzy match doesn't exist there", and that a query using it errors on refresh when opened on a Mac. That is a 2024 report from a named expert, not a current statement from Microsoft.

What points the other way. A vendor page that sells a competing tool says the opposite: that Power Query's Fuzzy Merge "is available in Excel for Mac". It is undated in the text we read, and it cites no Microsoft documentation. It is a seller's page, so weigh it accordingly. But it disagrees with the 2024 post, and software changes.

So there are two honest readings: it was missing as of mid-2024 and may have been added since, or it is still missing. You can settle it in under a minute: open Power Query on your Mac, choose Home, then Merge Queries, pick two tables and two columns, and look for the Use fuzzy matching to perform the merge checkbox. If it is there, use it. Microsoft's page shows how.

If it is not there, or if you need a file to work for colleagues on both Mac and Windows, keep reading. The MVP's advice for shared files is not to use fuzzy matching at all, because the query will error for the Mac user.

The free fix that needs no tool: clean, then merge exactly

Fuzzy matching is doing two jobs at once. It forgives case and punctuation differences, and it forgives small spelling differences. Most of the pain in real company lists is the first kind. You can do that part yourself.

Excel's exact-match lookups are already case-insensitive ("acme" finds "ACME"), so the real problems are punctuation, spacing and endings. The plan is: build a cleaned copy of the name in a helper column on each side, then merge or look up on the helper columns.

Steps (formulas, any Excel version)

Assume list 1 has names in column A, list 2 has names in column A of another sheet.

  1. Insert a helper column next to the names in each list. Call it Key.
  2. Remove punctuation. In the first helper cell, wrap the name in nested SUBSTITUTE calls, one per character you want gone: full stops, commas, apostrophes, ampersands. For example: 
    =LOWER(TRIM(SUBSTITUTE(SUBSTITUTE(SUBSTITUTE(A2,".",""),",",""),"'","")))
    The same formula does three jobs: removes the characters, trims stray spaces, and lowercases.
  3. Swap "&" for "and" (or the reverse) so "Smith & Sons" and "Smith and Sons" end up the same. Add one more SUBSTITUTE of "&" to "and" inside the formula. Do this before the LOWER, and keep spaces around it: SUBSTITUTE(x," & "," and ").
  4. Standardise the endings. Pick one form and rewrite the rest: " limited" to " ltd", " incorporated" to " inc", " l.l.c." handled by the punctuation step first and then " l l c" to " llc". One SUBSTITUTE per variant. Do the endings after you have lowercased, so you only write each variant once.
  5. Fill the formula down the whole column on both lists.
  6. Look up on the key. Use XLOOKUP, or INDEX/MATCH, on the Key columns instead of the raw names, with the exact-match option.
  7. Read the misses. Filter for the rows that still return no match. Those are the ones that need a person (or the next section).

The same idea in Power Query on Mac

This is the route the MVP's post describes: transform the text columns in both queries so they share a case (lowercase, uppercase or capitalised), then merge with fuzzy matching switched off. In the Power Query editor, select the column, then use the text transform commands (for example Transform, then Format, then lowercase and Trim) and repeat for the second query. Then use Merge Queries with an exact match on the transformed columns. For endings, use Replace Values on each query. Menu names can differ between versions, so treat the labels as a guide.

Note that we have not run these steps on a Mac. SUBSTITUTE, TRIM, LOWER, XLOOKUP and INDEX/MATCH are standard Excel functions, but test on a small sample before trusting it on a big file.

Tip: keep the original name

Do not overwrite the original names. Merge on Key, but keep the raw name beside it, so you can read both and spot a bad merge.

Where the free fix stops being enough

Cleaning is exact: two cleaned strings are either identical or not. That is why it fails on:

  • Abbreviations. "Intl Hardware Supply" and "International Hardware Supply". You would need a SUBSTITUTE for every abbreviation, and you do not know in advance which ones your data contains.
  • Missing characters. "OBrien and Sons" against "O'Brien and Sons" is fixed by the apostrophe step. "Obrian and Sons" is not.
  • Transposed words. "Sons Smith & Co" against "Smith & Sons Co".
  • Typos and near-spellings. "Smith Haulage" and "Smyth Haulage".
  • Extra or missing words. "The Globex Group" against "Globex". Stripping "the" and "group" helps for that one, but each new word you strip risks merging two different companies.

At that point you have three options: keep adding SUBSTITUTE rules and accept a long fragile formula, use a Windows machine where Microsoft's fuzzy merge is documented, or use something that scores how similar two names are.

The tool, last, and honestly scoped

Almost Equal is a free, single HTML file. It is not an Excel add-in and has no installer or account. You open it in a browser, load a .xlsx or .csv file (the page also accepts .xlsm, .xls, .tsv and .ods, but those have not been tested), choose the column of names, and it cleans each value (case, punctuation, accents, legal endings such as Inc, Ltd and Limited) and scores every pair by similarity. You see the cleaned version beside the original. Nothing is merged until you click Apply decisions, and pairs that are not identical after cleaning start unchecked, so you accept each one yourself. Download page.

What it does and does not do:

  • It finds near-duplicate rows inside one list. That is the whole of what is built. On the built-in sample data, "Acme Inc." and "ACME Incorporated" score 100, and "Smith Haulage" and "Smyth Haulage" score 97 and wait for your decision. Those are results on the sample, not an accuracy claim.
  • It is built to run with no network calls. The page makes no network requests; we recorded the browser's network panel through a full run, and it showed one request, for the page itself. We have not yet run it with the network adapter switched off, so test with the sample data before using your own file.
  • Limits. Free, with no purchase option. It reads the first 1,000 rows of the file you load. That means at most 1,000 distinct values and at most 499,500 comparisons per run.
  • It matches on one column at a time. It does not understand nicknames ("Bob" and "Robert"), match by sound, or read addresses. It does not change your original file; it produces new CSV or XLSX files.
  • Not tested on Mac. It is one static page meant for a current browser. No one on our side has yet run it on a Mac or in Safari, so if you try it there and it misbehaves, that is information we do not have yet. We have not compared its accuracy or speed against Power Query and make no claim either way.

It does not replace the cleaning steps above. Doing those first makes its list shorter and its scores easier to read.

If you have two lists and a one-list tool

This is a manual workaround, not a feature. Almost Equal has no mode for two lists. A tester ran the workaround below on a small made-up file and judged it usable but fragile, so read all three warnings before you try it.

The steps: paste the second list under the first in one sheet, with matching column layouts; delete the second list's header row; add a column of your own saying which list each row came from; save the stack as one file; load it; choose the name column; run Find duplicates.

Three things you must know before you use it:

  1. You add the tag column, and the tool will not ask you to. It never prompts for it. Without a column you filled in yourself, the downloaded files carry no information at all about which list a row came from. On screen, the row number is then the only hint. The exported log of removed rows names the matched partner by row number only, so you will need a lookup back into your sheet to see both sides of a pair.
  2. The 1,000-row cap covers both lists combined, so the practical limit is roughly 500 rows plus 500, not 1,000 each. The cap takes the first 1,000 rows of the stack. If your first list alone reaches 1,000 rows, the second list is discarded entirely, and the run still completes and shows proposals, looking successful. Check the row count on the loading banner before you trust any result.
  3. Duplicates within each list come back mixed in with the ones across lists, and pairs scoring 100 start accepted by default. In the test, a row from the first list was marked for removal because it duplicated another row in the same list, without the tester touching it. Review the 100-score pairs too. Expect extra proposals that have nothing to do with your question: in the test, about half of the proposals on a small stack were within-list pairs or false matches on a shared common word such as "Industries".

Also: borderline pairs you leave undecided appear in none of the downloads, so a "probably the same, check by hand" list has to be written down by you from the screen.

If that is more spreadsheet work than the job deserves, a tool built for two lists is the better answer. This one is not that tool.
